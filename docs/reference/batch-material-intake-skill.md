# 批量采购物料准入 Skill

## 目标

把采购清单逐行分入四个业务队列，先分析，不写 ERPNext：

```text
采购清单
  -> DeepSeek 提取名称与明确规格事实
  -> 标准名称字典确定物料类型
  -> 属性模板检查采购信息
  -> 发布目录检查现有 SKU
  -> 已有 SKU / 新增 SKU / 新增标准类型 / 需要补充
```

## 职责边界

- DeepSeek 负责理解旧称、品牌、型号、尺寸和自然语言规格。
- 原采购表负责数量和单位；模型回传的数量、单位不会覆盖原始事实。
- `MaterialTypeClassifier` 负责类型边界、属性字段对齐、必填项和重复 SKU 判断。
- 现场只需提供足以区分实际用品的经验口径；缺少的系统属性优先从已批准的企业标准 SKU 或同类型共同默认值补齐。
- 采购单位按现场清单保留；与库存单位的包装换算延后到报价或收货阶段确认，不阻塞物料准入。
- `BatchMaterialIntakeAnalyzer` 保留每一行并生成四类队列。
- 首版每次最多 50 行，DeepSeek 按 20 行分块并行抽取，最多 3 路并发；数量和单位由原始清单本地保留，不重复交给模型判断。
- 分析结果不修改物料发布目录，也不写 ERPNext。

## 四个队列

| 队列 | 含义 | 后续动作 |
|---|---|---|
| 已有 SKU | 规格完整且唯一命中现有 SKU | 进入采购业务准备 |
| 现有类型新增 SKU | 类型已存在、规格完整、没有重复 SKU | 生成建档确认卡 |
| 需要新增标准类型 | 标准名称字典没有可靠类型 | 物料管理员确认分类和属性模板 |
| 需要补充或选择 | 标准目录补齐后仍无法区分实际用品 | 只追问现场真正需要决定的信息 |

## 页面与接口

```text
http://127.0.0.1:8788/material-intake-lab
POST /api/material-intake/analyze
```

页面接受制表符或竖线分隔的四列：材料、规格、采购数量、单位。结果可以按四个队列筛选并查看判断依据、属性和候选证据。

页面的“处理过程”包含两层追踪：

- 整批追踪：读取、事实抽取、目录匹配、标准属性补齐、准入队列五个阶段分别记录输入行数、输出行数、耗时、部分阻塞状态和关键统计。
- 单行追踪：点击任意结果行，可查看原始现场文字、模型提取字段、字段来源、标准名称匹配、企业默认属性补齐和最终队列依据。

追踪数据来自实际分析结果，不展示模型隐藏思维；“部分待处理”表示只有部分物料需要人工确认，不代表整批分析失败。

## 当前限制

- 当前只完成准入分析，尚未把结果批量编译成建档和采购确认任务。
- 含糊名称不会由模型擅自补造关键采购规格。
- 采购单位与库存单位不同且没有换算关系时必须确认。
- DeepSeek 延迟仍受网络和模型负载影响；当前通过减少分块次数、限制并发和网络重试降低等待，后续可改为分块流式返回。
