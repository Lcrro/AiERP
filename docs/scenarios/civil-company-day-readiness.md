## 测试顺序建议

第一轮只跑“低风险草稿线”：

```text
08:00 异常查看
-> 08:20 城东劳保材料申请草稿
-> 09:30 采购汇总
-> 10:00 劳保采购订单草稿
-> 11:20 库存检查
-> 14:30 项目领料草稿
-> 18:00 收尾摘要
```

第二轮再加入提交和源单引用：

```text
提交 Material Request
-> 从 MR 创建 PO 草稿
-> 提交 PO
-> 从 PO 创建 PR 草稿
-> 提交 PR
-> 从 PR 创建 PI 草稿
```

第三轮处理异常路径：

```text
采购收货规格不符
-> 记录差异 Comment
-> 创建采购/质检 ToDo
-> 生成退货上下文
-> 人工确认后创建退货草稿
```

## 不提前创建的内容

这些内容必须在时间线测试中现场创建，不能放进 seed：

- 当天的 `Material Request`
- 当天的 `Purchase Order`
- 当天的 `Purchase Receipt`
- 当天的 `Purchase Invoice`
- 当天的项目领料 `Stock Entry`
- 当天由异常触发的新 `Comment` 和新 `ToDo`

这样每次测试都能清楚看到某一步 ToolCall 到底产生了什么。
