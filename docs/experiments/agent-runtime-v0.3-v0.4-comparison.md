```text

→ DeepSeek 自主规划循环
→ Capability 发现与 Guide
→ Resolver
→ Pydantic 业务意图

```

冻结时基线：

- `20 / 20` Capability 严格真实 DeepSeek 基准通过。
- 全量自动化测试：`377 passed, 3 skipped`。
- 写操作必须确认，底层写入旁路为 `0`，重复写单为 `0`。
- 已知体验问题：部分任务规划往返较多、追问较碎、重复发现或解析、技术错误偶尔进入员工回复。

## 公平对照原则

两个版本必须使用：

1. 同一份代码外的 ERPNext 黄金账套快照。
2. 同一员工、项目、仓库、权限和主数据。
3. 同一 DeepSeek 模型、温度和 API 配置。
4. 同一批自然语言输入，不为某个版本改写题目。
5. 写操作从相同业务单据零状态开始，并在每轮后恢复账套。
6. 真实结果以 ERPNext 回读为准，不能把自然语言回答正确当作业务成功。

## 固定场景

首批至少覆盖：

| 场景 | 关键难点 |
|---|---|
| 查询“当前库存里有什么” | 模糊范围、是否需要先追问物料 |
| 申请帆布手套并要求明天到货 | 候选物料、相关仓库存量、日期和数量 |
| 创建水泥材料申请 | 多候选规格、单位、项目仓库 |
| 从材料申请发起询价 | 来源状态、候选供应商、截止时间 |
| 从供应商报价生成采购订单 | 来源关系、金额、交期和防错工具选择 |
| 从采购订单办理收货 | 剩余数量、目标仓库和部分收货 |
| 到货规格不符并全部退货 | 原收货单、退货数量、评论和待办 |
| 项目领料 | 实时库存、项目和成本中心 |
| 查询应付并准备付款 | 公司、供应商、来源发票和本人权限 |
| 引用“刚才那张单”继续操作 | 跨轮业务记忆和单号消歧 |

## 人工体验评分

用户在不知道版本的情况下按 1–5 分评价：

- 像不像懂业务的助理。
- 是否一次问清必要信息。
- 是否提供了做决定所需的候选、库存和来源事实。
- 回复是否自然、简洁、可信。
- 完成任务是否省事。

测试页面只显示版本 A / B，不显示实现名称。最终同时比较业务正确性和体验，不能只比较对话流畅度。

## v0.4 实验约束

- 可以替换 Runtime 的规划方式，但复用同一 ERPNext Adapter、员工凭据和黄金账套。
- 可以改变会话状态结构和模型交互协议。
- 不允许削弱身份、权限、写入确认、幂等和 ERPNext 回读验证。
- 新方案未胜出前，v0.3 存档始终保留为可运行回退版本。

## v0.4 实验 01：字段槽位与操作模板

第一项实验不替换现有 Runtime，只验证把复杂 ToolCall 拆成关系化字段槽位是否能降低参数编排复杂度。

- 说明文档：[字段槽位与操作模板模型](../architecture/field-slot-operation-model.md)
- 可视化页面：`http://127.0.0.1:8788/operation-model`
- 首个样板：`op.material_request.create`
- 验证重点：字段来源、缺失定位、派生字段、规则校验和确定性 ToolCall 编译。
