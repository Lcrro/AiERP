# Material Group Governance v0.1

本文档说明 2024 采购 review 物料分类的第一版治理方案。治理目标是把人工整理时产生的过细、同义、倒置结构分类，映射到一套更稳定的 canonical group taxonomy，供 ERPNext Item Group 规划和 Agent 检索使用。

本次治理不修改 ERPNext，不删除原始 reviewed group path，不把待确认物料自动变成可建档物料。原始路径继续作为审计、追溯和回放规则的依据。

## 产物

- 映射 CSV：`data/material_purchase_2024/material_group_canonical_mapping.csv`
- 生成脚本：`scripts/export_material_group_mapping.py`
- 回归测试：`tests/test_material_group_mapping.py`

映射 CSV 字段：

| 字段 | 含义 |
| --- | --- |
| `reviewed_group_path` | 人工 review 阶段的原始分类路径 |
| `canonical_group_path` | 治理后的标准分类路径 |
| `canonical_level1` | 标准一级分类 |
| `canonical_level2` | 标准二级分类 |
| `canonical_level3` | 标准三级分类 |
| `confidence` | 规则置信度，0-1 |
| `rule_reason` | 命中的合并或关键词规则 |
| `needs_human_review` | 是否需要人工复核后才能用于建档策略 |

## 分类原则

1. 保留业务语义，不追求一次性全行业完美分类。v0.1 先解决采购清单中已经出现的制造业高频物料。
2. 优先统一一级域，再统一二级/三级。比如 `电气`、`电气材料`、`电气耗材` 统一到 `电气与自动化`。
3. 将“同义词”和“结构倒置”映射到同一 canonical path。比如 `劳保耗材/手套` 和 `劳保用品/手套` 均映射到 `劳保用品/手部防护/手套`。
4. 对能稳定识别的具体品类使用关键词规则。比如 `断路器`、`漏电`、`空开` 映射到 `电气与自动化/低压电器/断路器`。
5. 对只完成一级合并、二级含义尚不稳定的路径，落到 `其他/<原二级>`，并标记 `needs_human_review=true`。
6. 原始路径不被覆盖。后续可以用映射表驱动 ERPNext Item Group 建议、检索扩展和人工治理工作台。

## 人工确认策略

以下分类即使规则能给出较高置信度，也默认标记 `needs_human_review=true`，原因是它们会影响安全、合规、作业许可或库存建档边界：

- 安全类：安全带、安全绳、高处防护、登高、水域防护、防爆相关物料。
- 吊装类：吊带、卸扣、吊钩、钢丝绳、索具连接件，需要确认载荷、材质、标准和报废管理要求。
- 消防类：灭火器、消防水带、消防接头、消防工具，需要确认消防认证、规格、有效期和维保责任。
- 危化/化学品：危化品、清洗剂、除锈剂、胶粘剂、油漆稀料等，需要确认 MSDS、储存条件和采购合规属性。
- 压力/防爆/气瓶类：需要和设备、安全或 EHS 负责人确认是否应进入专用台账。
- 待确认物料：来自 `manual_review_queue_from_review.csv` 的待确认项不能因为分类映射而自动变成可建档。

人工复核通过前，映射表只能用于检索扩展、治理建议和报表统计，不应直接触发 ERPNext 建档。

## 脚本维护方式

`scripts/export_material_group_mapping.py` 使用三层规则：

1. `L1_ALIASES`：一级分类同义词表，例如 `电气材料 -> 电气与自动化`。
2. `RULES`：按 canonical 一级分类组织的关键词规则，用于识别二级和三级。
3. `PATH_OVERRIDES`：少量人工指定路径，用于锁定关键示例或处理关键词无法表达的结构倒置。

维护建议：

- 新增同义一级分类时，优先补 `L1_ALIASES`。
- 新增稳定品类时，补 `RULES`，避免为每条原始路径写 override。
- 只有当单一路径需要覆盖通用规则时，才补 `PATH_OVERRIDES`。
- 每次改规则后运行脚本和测试：

```powershell
python scripts/export_material_group_mapping.py
pytest tests/test_material_group_mapping.py -q
```

## 后续协调问题

- 是否将 `canonical_group_path` 作为 ERPNext Item Group 的候选树，需要主线程确认 ERPNext 现有 Item Group 命名和父子层级。
- `其他/<原二级>` 的 289 条复核项中，有一部分只是规则未覆盖，不一定业务上高风险；需要后续按采购金额、使用频次或库存影响排序治理。
- 非库存服务应继续留在服务项路径，不参与库存 Item 自动建档。
