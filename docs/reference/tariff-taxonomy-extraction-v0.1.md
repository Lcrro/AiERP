# 税则多层目录提取台 v0.1

## 目标

把《中华人民共和国进出口税则（2026）》的公开 PDF 转成 Nexterp 可审核的候选分类目录，用来减少跨行业物料分类从零设计的工作量。此工具只负责提取和校验，不把海关税则直接等同于 ERPNext 的 Item Group，也不替代物料准入规则。

当前公开源固定为财政部税收制度司发布的 PDF：

`https://gss.mof.gov.cn/gzdt/zhengcefabu/202512/P020251231607833453633.pdf`

已知基线为约 70 MB、1492 页、原生文本层。全量任务只接受该域名的 HTTPS 地址，避免把任意远程文件当成内部分类输入。

## 页面和任务模型

打开 `http://127.0.0.1:8788/tariff-extraction-lab` 可以看到可视化任务页。页面提供两个模式：

- 演示模式使用固定的螺栓、螺母、垫圈样本，不访问网络，用来检查阶段、进度环、吞吐图、节点表和日志。
- 全量模式需要页面勾选明确确认，后台才会下载 PDF 并按页提取。当前全量任务还只生成候选 JSONL 和 manifest，不写入 ERPNext。

全量提取完成后，打开 `http://127.0.0.1:8788/tariff-taxonomy-browser` 浏览完整五层结构。浏览器按父级懒加载节点，支持每层折叠/展开、“展开到章”、税号或名称全库搜索、层级筛选，以及从搜索结果直接展开并定位完整祖先路径。

后台阶段是：排队、下载源文件、检查 PDF、提取目录、整理多层类目、校验、生成候选包、完成。每个任务都带有任务 ID、阶段进度、总体进度、页数、节点数、8 位税号数、待复核数、速度、ETA、最近节点和最近日志。

候选输出位于 `.runtime/tariff-extraction/<job_id>/`，包括：

- `tariff-nodes.jsonl`：每行一个候选节点，含 `code`、`name`、`level`、`parent_code`、`page`、`kind`；
- `manifest.json`：源版本、生成时间、各层节点数、缺失父级数、层级完整性和 `erpnext_written: false` 安全标记。

坐标解析的完整目录固定为五层：

1. `section`：21 个“类”，内部编码使用 `S01` 至 `S21`；
2. `chapter`：96 个两位“章”（第 77 章保留未用）；
3. `heading`：1,228 个四位品目；
4. `subheading`：5,612 个六位子目；
5. `sku`：8,972 个八位税号叶节点。这里的 `sku` 仅表示税则叶节点，不是已准入的 Nexterp SKU。

当前完整基线共 15,929 个节点。除 21 个根“类”外，每个节点都必须有可回读的直接父级；任何缺失、重复或跨级关系都会进入校验问题，不能标为 `hierarchy_complete: true`。

## 处理边界

PDF 解析优先使用 PyMuPDF 的坐标词元：税则号列约在 x=61..97，货品名称约在 x=100..223，税率列从约 x=242 开始。这样可以排除前言和法律注释中出现的税号。“类”和“章”从表格上方居中的官方标题提取；四位品目从编码列提取；六位子目由八位税号前六位与名称列的短横线缩进上下文共同恢复；八位税号保持原名称和来源页码。相同六位前缀存在多个国内细分税号时，取它们共同的上级路径，避免把第一个八位税号名称误当作整个六位子目。若环境没有 PyMuPDF，程序才回退到 pypdf 文本解析；该回退结果没有完整坐标层级，必须人工复核，不应直接发布。

例如 `73181510` 的父链为：`S15 贱金属及其制品` → `73 钢铁制品` → `7318` → `731815 螺纹制品 / 其他螺钉及螺栓` → `73181510 抗拉强度在 800 MPa 及以上…`。

## 六位层级修复 v0.4

短横线层级状态按同级替换、下级继承处理：当前编码行会先替换同一短横线深度的旧兄弟节点，再生成六位子目名称；页末尚未消费的一级或二级父标题会传递到下一页，但不会拼入八位税号的官方行名称。税率脚注、关税配额说明和公式片段按语义排除，同时保留合法的 `ex` 补充货品描述。

全量重建继续保持 15,929 个节点、8,972 个八位税号和全部父级编码不变。相对旧包修正 1,761 个六位子目名称，并清理 14 个混入货品名称的税率说明。自动审计覆盖 400 个跨页风险边界，其中 349 个需要六位父标题继承，失败为 0；同级兄弟串联残留为 0。`2801` 的验收结构为 `280110 氯`、`280120 碘`、`280130 氟；溴`。

## 唯一 xx00 子目与无编码分组修复 v0.5

若一个四位品目只有唯一的六位子目，且该子目编码为四位品目加 `00`，则六位范围与四位品目完全一致，六位名称直接继承完整四位名称，不再从某个国内八位细分中挑选候选名称。全库共有 271 个此类结构，重建后逐项校验名称一致，编码和父级关系均未变化。

短横线深度 3 及更深的无编码分组属于国内八位细分语义。由于固定五层树不单独创建虚拟分组节点，解析器将这些分组扁平写入所属八位税号名称，并跨页保留到同组后续兄弟。全库为 1,010 个八位名称补齐上下文；每个新名称均以原名称结尾，未发现重复分组。`2501` 的验收结构为 `250100` 继承完整“盐……纯氯化钠……海水”名称，其下为 `25010011 盐：食用盐`、`25010019 盐：其他`、`25010020 纯氯化钠` 和 `25010030 海水`。

这一步完成后仍需要：

1. 抽样检查螺栓等高密度类目的名称和层级；
2. 建立海关税号到 Nexterp 内部 `top_group / material_family / standard_type` 的映射；
3. 冻结版本、生成差异报告，再由业务人员确认发布；
4. 通过物料准入闭环显式确认后，才允许创建标准类型/SKU、同步 ERPNext 并回读验证。

## 本地依赖

全量模式默认使用 `PyMuPDF` 读取坐标列，`pypdf` 作为回退解析器。安装项目依赖后即可启用：

```powershell
python -m pip install -e .
```

如果运行环境缺少 `pypdf`，演示模式仍可用，全量模式会在任务记录中报告安装提示并保持不写入 ERPNext。
