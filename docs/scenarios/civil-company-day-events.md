# 小型土木公司一日运转模拟：时间顺序事件流

本文按一天的真实业务时间顺序描述盛拓工程有限公司的业务运转。用途是把“员工说人话 -> Agent 生成 ToolCall -> ERPNext 产生单据/报表/提醒”的链路拆成可测试事件。

关联角色表：[小型土木公司一日运转模拟：员工角色表](civil-company-day-roles.md)

## 场景目标

这个场景用于验证以下能力：

- 项目班组能用自然语言提材料需求。
- 采购能从材料申请继续生成采购动作。
- 仓库能处理收货、发料、库存不足和规格不符。
- 财务能看到采购发票、应付和项目成本。
- 管理层能看到当天异常摘要。
- Agent 能把跨部门业务从单步 ToolCall 串成完整流程。

## 公司与项目

公司：盛拓工程有限公司

项目：

- 城东道路改造项目
- 南区排水管网项目
- 西站配套设施项目

仓库：

- 中心仓
- 项目仓

## 可转成测试用例的链路

### 链路一：项目提料到采购订单

```text
班组长说人话提需求
-> Agent 匹配物料
-> 创建 Material Request 草稿
-> 项目经理确认提交
-> 采购汇总 Pending 材料申请
-> 创建 Purchase Order 草稿
```

### 链路二：采购到货到退货

```text
供应商送货
-> 仓库按采购订单创建 Purchase Receipt
-> 发现规格不符
-> 质检记录原因
-> 采购发起 Purchase Receipt Return
-> 供应商联络员跟进退换货
```

### 链路三：库存领料到项目成本

```text
项目仓查询库存
-> 班组确认领料
-> 创建 Stock Entry Material Issue
-> 关联 Project / Cost Center
-> 财务查看项目成本变化
```

### 链路四：管理层异常日报

```text
查询逾期采购订单
-> 查询低库存和缺料
-> 查询退货和质检异常
-> 查询付款到期
-> 汇总为管理层摘要
```

## 对 Agent Runtime 的要求

每个事件都应该能记录：

- 用户原话
- 用户身份和岗位
- Agent 解析出的意图
- 生成的 ToolCall
- ERPNext 返回的 ToolResult
- 是否需要用户确认
- 是否产生单据、待办、评论或提醒
- 是否进入管理层异常摘要

## 后续落地建议

优先把以上事件拆成三类数据：

- `scenario_users`：员工、岗位、权限、所属项目或部门
- `scenario_master_data`：供应商、仓库、项目、物料、价格
- `scenario_events`：按时间顺序执行的业务动作

这样后续可以写成自动化沙盘脚本，反复验证 ToolCall 是否真的能支撑日常业务。
