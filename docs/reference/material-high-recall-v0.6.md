# 物料批量高召回检索与 DeepSeek 判定 v0.6

## 目标

材料接入分析只负责给出可审查的准入结论，不写入 ERPNext：

```text
整批清单
-> DeepSeek 按 20 行提取事实
-> 类型和 SKU 并行高召回
-> 动态门槛与候选分组
-> DeepSeek 按块比较真实候选
-> 程序复核
-> 已有 SKU / 新增 SKU / 新增类型 / 需要选择
```

## 召回规则

- 编码、确认别名或名称加至少两个明确规格：门槛 80。
- 名称或别名加一个关键规格：门槛 65。
- 模糊名称、俗称或缺少规格：门槛 50。
- 没有候选达到门槛时保留最高 3 项作为参考，不自动判定为已有 SKU。
- 关键规格冲突的 SKU 可以帮助判断“同类型新增 SKU”，不能直接复用。
- 类型和 SKU 同时检索，不能先锁定一个类型后再缩小搜索范围。

候选统一为 0-100 分，并保留名称、别名、属性命中、冲突和匹配依据。候选不超过 20 项时完整送入判定；超过 20 项时按类型和规格差异分组，每组最多提供 3 个代表，服务端仍保留本次完整召回结果。

## 批量与模型边界

- 每批最多 50 行，每 20 行一个处理块，最多 3 个块并发。
- 每个处理块进行一次事实提取和一次 DeepSeek 候选比较，不逐行反复调用模型。
- DeepSeek 只能从服务端返回的真实 `type_id`、`item_code` 和候选规格中作判断。
- `existing_sku`、`new_sku`、`new_type` 均由程序复核；编码未知、规格冲突或证据不足自动进入 `needs_input`。
- DeepSeek 超时或结构校验失败时保留召回候选，但不生成放行结论，也不学习别名。

## 别名学习

分析过程不写别名。员工明确确认候选后，调用：

```text
POST /api/material-intake/confirm-alias
```

确认记录写入 `data/material_master/runtime_aliases.jsonl`，包含叫法、目标类型或 SKU、确认员工、来源行和时间。别名可一对多，默认指向标准类型；只有叫法本身包含完整 SKU 识别规格时才指向具体 SKU。

## 页面验收

`/material-intake-lab` 的处理过程应显示：读取、事实提取、高召回检索、候选压缩、DeepSeek 判定、程序复核和处理结论。点击任意行可以查看动态门槛、候选数量、分数构成、完整候选、分组摘要、模型判定和程序复核结果。

分析接口仍为：

```text
POST /api/material-intake/analyze
```

所有分析结果必须标记 `writes_erpnext=false`。
