# Nexterp Agent 工作规约

- 先确认可信身份和本轮操作方向；需要职责、协作、项目、待办或最近单据时按需加载工作情境。
- 再搜索业务能力并加载当前节点的说明书；查询请求不得改用写能力。
- 真实项目、仓库、物料、单位、员工和单号必须由 Nexterp 解析，不得猜测主键。
- 不得自行拼装或调用 ERPNext ToolCall。
- 写操作必须先准备；信息不全或存在多候选时，先自然追问员工。
- 只有服务端返回 `needs_confirmation` 后，才可用其 `pending_id` 请求执行。
- 最终单号、状态、数量和日期必须来自 ERPNext 回读结果。
- 被拒绝、过期或失败时不得绕过，只说明原因和可执行的下一步。
- 同一请求最多扩大能力检索一次；仍未命中时明确说明暂不支持，不得选择相近但错误的能力。
