# 土木进销存 Agent v1.0

## 产品目标

以 UP 事业部真实组织、项目、仓库和物料主数据为基础，贯通：

```text
员工自然语言
  -> DeepSeek 自主规划
  -> 按需发现 ToolCall
  -> Resolver 查询真实主键
  -> 员工确认写操作
  -> ERPNext 员工账号执行
  -> 返回真实单据和业务结果
```

## 当前基线

- ERPNext 工具层、Tool Contract、ToolGateway 和员工身份执行已具备。
- 物料发布表和基础主数据发布包已形成稳定来源。
- 独立 ERPNext 开发账套可通过 `plan/apply/verify` 重建。
- DeepSeek 自主规划 Runtime 和员工工作台已接入。
- 旧业务模拟数据、脚本、报告和会话状态已清理。

## 后续交付顺序

1. 用当前项目主数据重新验证“候选物料 + 相关仓库批量库存”只读链路。
2. 验证材料申请草稿的多轮澄清、确认、幂等和员工身份。
3. 逐步验证采购订单、收货、退货、发票和项目领料。
4. 为每条链路补结构化模拟模型序列和本地 ERPNext 集成测试。
5. 集中加固权限、审计、失败恢复、重复请求和会话引用。

## 开发口径

- DeepSeek 负责目标理解和下一动作规划，不直接编造 ERPNext 主键。
- 物料、项目、仓库、供应商、公司和单号由 Resolver 或 ERPNext 结果提供。
- 只读工具可以自动执行；所有写操作必须先确认。
- ToolGateway 检查工具暴露和当前员工身份，ERPNext 做最终权限裁决。
- 集成测试产生的交易记录必须可识别、可重复清理，不进入权威主数据。

## 验收标准

- 任意同义表达不需要新增关键词分支。
- 工具按需发现，不一次向模型加载全部 schema。
- 候选物料及相关仓库库存来自同一次实时查询，不使用跨任务缓存。
- 多候选时清楚展示差异并询问员工；高置信候选仍需遵守写操作确认。
- 返回的单号、数量、金额和状态必须来自 ToolResult。
- 权限不足、身份不一致和实体歧义不能被模型绕过。
