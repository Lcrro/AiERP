# 采购闭环与员工工作台 v0.3

## 目标

材料申请链路已经完成首轮贯通。下一阶段以真实采购业务为主线，把员工从提出需求到完成收货或退货的全过程放进工作台：

```text
材料申请
  -> 三级审批
  -> 待采购汇总
  -> 询价与报价比较
  -> 采购订单
  -> 到货与采购收货
  -> 差异处理与采购退货
  -> 进度、待办和审计闭环
```

工作台负责员工体验，DeepSeek 负责理解模糊目标和多步规划，ERPNext 继续作为单据、权限、库存、工作流和审计的唯一事实来源。

## 范围

本版本覆盖：

- 材料员、材料设备主管、项目经理、采购人员和仓库人员的采购协作。
- Material Request、Request for Quotation、Supplier Quotation、Purchase Order、Purchase Receipt 和采购退货。
- 工作台中的待办、进度、单据详情、直接业务按钮和 Agent 自然语言代办。
- 从真实 ERPNext 状态生成流程提示、通知和可执行动作。

本版本暂不覆盖：

- 采购发票、付款和完整财务结算。
- 正式单点登录、邮件和企业即时通信通知。
- 销售、生产、资产等其他业务模块的岗位工作台。

## 实施阶段

### A. 材料申请收尾

状态：**已完成（2026-07-15）**

目标：把已经跑通的链路整理成稳定基线，而不只是“能够建出一张单”。

- 材料申请行显示测试参考价和预计金额，并明确它不是供应商正式报价。
- 参考价只能来自物料发布表或 ERPNext 价格数据，DeepSeek 不得自行编造。
- 单据抽屉展示当前流程节点、已完成动作、审批人和时间。
- 驳回必须填写原因；材料员能看到原因、修改并重新提交。
- 建单、提交、主管审批、项目经理审批均使用对应员工身份。
- 修复成功建单后 Agent 最终回复失败等假失败问题。

验收场景：毛晓泉创建有参考价的材料申请，潘丰驳回并填写原因；毛晓泉修改后重新提交，潘丰和胡银虎依次批准，最终 `docstatus=1`，工作台完整显示流程记录。

验收记录：

- 单据：`MAT-MR-2026-00016`
- 物料：`MAT-CEM-000008`，数量 `2 包`
- 测试参考价：`28 元/包`，预计金额 `56 元`
- 流程：毛晓泉提交 -> 潘丰驳回并填写原因 -> 毛晓泉重提 -> 潘丰批准 -> 胡银虎批准
- 最终状态：`workflow_state=已批准`，`docstatus=1`
- 工作台：桌面与 `390px` 窄屏均能查看审批记录、驳回原因、预计价格和明细
- 自动测试：`244 passed, 3 skipped`

### B. 待采购工作台

目标：让采购人员知道“哪些已批准需求需要我处理”。

- 汇总已批准且仍有未采购数量的材料申请行。
- 按项目、需求日期、紧急程度、物料族和建议供应商筛选。
- 同一物料跨项目需求既能分别查看，也能形成合并采购建议。
- 展示申请数量、已订购数量、剩余数量、库存信息和需求日期。
- 支持勾选需求行进入询价或直接采购，但不自动作出采购承诺。

验收场景：采购人员登录后只看到权限范围内的待采购需求，已完全下单的申请不再进入待采购队列，部分下单的申请显示准确剩余量。

### C. 询价与报价

目标：完成复杂或价格不确定物料的多供应商询价与比价。

- 从选中的材料申请行创建询价单，保留源申请和项目关系。
- Resolver 提供真实供应商候选，员工确认后加入询价。
- 供应商报价可以录入价格、交期、税费、付款条件和有效期。
- 比价视图同时比较总价、单价、交期和条件，不只按最低价排序。
- 选定报价前需要员工确认，Agent 只能给建议和理由。

验收场景：赵强为同一批管材向至少两家供应商询价，录入两份报价，工作台给出可解释比较，并能选定其中一份进入采购订单。

### D. 采购订单

目标：把批准需求或选定报价转换为正式采购承诺。

- 支持从已批准材料申请和供应商报价创建采购订单草稿。
- 自动带出源单、物料、数量、单位、项目、仓库、价格和交期。
- 创建前校验剩余可订购数量，避免重复或超量下单。
- 根据 ERPNext 权限和工作流显示提交、批准、驳回和取消按钮。
- 工作台展示订单的已收货、待收货、已开票和延期状态。

验收场景：采购员从材料申请创建采购订单，系统保留源行引用；重复创建时只能采购剩余数量，订单批准后进入待收货列表。

### E. 采购收货

目标：仓库人员能够按采购订单办理真实入库。

- 从已提交采购订单创建采购收货草稿。
- 展示订单数量、历史已收数量、本次可收数量和目标仓库。
- 支持实际数量、批次或序列号、质检结果和到货备注。
- 提交前明确展示将受影响的仓库和库存数量。
- 提交后验证 Stock Ledger Entry 和 Bin 的实际库存变化。

验收场景：王海按采购订单收货，部分到货时订单保留未收数量；全部到货后订单状态正确，仓库库存增加量与收货单一致。

### F. 到货差异与采购退货

目标：规格不符、质量不合格或数量异常时，员工能够留下完整证据并完成退货。

- 在收货单记录差异类型、原因、照片或附件、责任人和跟进 ToDo。
- 未入库货物支持拒收记录；已入库货物通过采购退货单冲回库存。
- 退货草稿必须引用原采购收货单，并限制为剩余可退数量。
- 提交退货后验证库存反向变化和原单退货比例。
- 工作台将异常单据进入“异常与退回”，直到处理完成。

验收场景：一批材料规格不符，仓库记录差异并通知采购；对已入库数量创建全量退货，提交后库存恢复、源收货单可追溯、异常状态关闭。

### G. 角色工作台

目标：不同员工进入系统后首先看到自己今天要处理的工作。

- 材料员：我的申请、被驳回申请和需求进度。
- 材料设备主管：待审批申请、待采购需求和异常升级。
- 项目经理：项目审批、紧急缺料和项目采购进度。
- 采购人员：待询价、待下单、延期订单和供应商跟进。
- 仓库人员：待收货、部分到货、质检和退货处理。
- 所有列表由 ERPNext 权限裁剪，工作台不维护第二套角色授权。

验收场景：同一张单据在不同角色工作台显示不同的可见信息和可执行动作；越权调用按钮或 API 均被拒绝。

### H. Agent 自然语言协作

目标：员工可以用自然语言完成上述流程，但明确按钮仍直接调用 ERPNext。

- Agent 能查询“刚才的申请”“这个项目未到货订单”等结构化上下文。
- 实体主键必须来自 Resolver 或真实 ToolResult，不能凭空生成。
- 多候选时显示业务卡片供员工选择；高置信度也要在写入前给出摘要。
- 每次写操作独立确认，确认后执行原 ToolCall，不让模型重新规划。
- Agent 的最终回复只能引用真实单号、状态、数量和金额。
- Agent 失败时说明具体字段、权限或业务条件，并给出下一步。

验收场景：员工说“把刚才批准的水泥申请询价”“这批到货规格不对，全部退掉”，Agent 能跨多步查询并准备正确操作，每次写入均等待确认。

### I. 完整回归与可重复沙盘

目标：每次修改 Runtime、ToolCall 或工作台后，都能快速证明采购链路没有退化。

- 建立一套带测试标记的项目、物料、供应商和交易数据。
- 提供可重复的准备、运行、验证和清理命令。
- 自动验证源单引用、剩余数量、审批历史、库存变化和权限隔离。
- 覆盖正常采购、部分收货、延期、驳回重提和全量退货。
- 保留关键 Agent 动作轨迹和 ToolResult，但不保存模型隐藏推理。
- 桌面和窄屏工作台均完成截图与交互验证。

验收场景：从一条自然语言材料需求开始，按真实角色完成申请、审批、询价、报价、订单、收货和退货；清理后可再次从零运行。

## 实施顺序

严格按以下顺序推进，每个阶段验收通过后再进入下一阶段：

```text
A 材料申请收尾（已完成）
-> B 待采购工作台
-> C 询价报价
-> D 采购订单
-> E 采购收货
-> F 采购退货
-> G 角色工作台
-> H Agent 自然语言
-> I 完整回归
```

每一阶段都遵循同一开发节奏：

1. 先用对应员工在 ERPNext 中确认原生业务动作和字段。
2. 补齐或复用专用 ToolCall、Resolver 和 Adapter 行为。
3. 在工作台实现读取、单据卡和直接业务按钮。
4. 再让 DeepSeek 通过工具发现和契约使用同一能力。
5. 依次完成单元测试、本地 ERPNext 集成测试和人工角色验收。
6. 记录验收单号和结果，清理可清理的测试交易数据。

## 总体验收标准

- ERPNext 始终是库存、单据、权限和审批状态的唯一事实来源。
- 所有写操作使用当前员工本人凭据，并经过明确确认。
- 工作台按钮不请求 DeepSeek；自然语言代办才进入 Agent Runtime。
- 任何业务主键均来自 Resolver、ERPNext 查询或既有会话结果。
- 源单与后续单据之间的引用、数量和状态可完整追溯。
- 员工只看到与其项目、岗位和 ERPNext 权限一致的数据与动作。
- 工作台能够解释当前进度、下一处理人、异常原因和可执行下一步。
- 全采购闭环具备自动回归和可重复清理能力。
